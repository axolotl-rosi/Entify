# Entify 위협 모델과 잔여 위험

최종 업데이트: 2026-10-15

## 신뢰 경계

Entify가 직접 통제하는 범위는 앱 프로세스, 앱 전용 저장소, 배포 저장소와 다운로드 사이트입니다. Android OS, Android System WebView, 기기 제조사 펌웨어, 엔트리 서버와 엔트리 페이지 코드는 외부 신뢰 경계입니다. 앱은 엔트리 API 형식을 임의로 바꾸지 않지만 응답 크기, URL, 이미지 형식과 메시지 출처는 로컬에서 검증합니다.

## 보호 자산

- 세션 쿠키, CSRF 토큰, x-token
- 알림 원문, 사용자 식별자, 프로필과 작품 URL
- 배포 APK의 서명 계보와 SHA-256
- 사용자의 알림 숨김, 방해금지, 읽음 상태

## 현실적으로 방어하는 공격

- 평문 설정 파일·Android 백업을 통한 세션 유출
- HTTP 전송, 사용자 설치 CA, 혼합 콘텐츠를 이용한 일반적인 감청
- 외부 앱의 컴포넌트 직접 호출과 알림 PendingIntent 변조
- 허용되지 않은 WebView 출처·하위 프레임·외부 링크의 메시지 주입
- 비정상적으로 큰 API·HTML·이미지 응답과 이미지 디코딩 자원 고갈
- logcat, 화면 캡처, 최근 앱 미리보기와 화면 오버레이를 통한 우발적 노출
- 다운로드 파일 교체를 사용자가 탐지하지 못하는 공급망 혼동

## 완전히 방어할 수 없는 공격

- 루트 권한, Frida/Xposed, 커널·펌웨어 침해를 가진 공격자의 메모리·앱 데이터 접근
- 잠금이 해제된 기기의 악성 접근성 서비스 또는 사용자가 승인한 화면 공유
- 엔트리 공식 출처에서 실행되는 XSS가 그 페이지 자체의 세션 권한으로 수행하는 동작
- 개발자 계정·서명 키·Vercel 또는 GitHub 계정이 탈취된 공급망 공격
- 사용자가 해시를 확인하지 않고 비공식 미러의 APK를 설치하는 경우

루팅 탐지와 Frida 탐지는 우회 가능하므로 보안 경계로 사용하지 않습니다. 탐지를 추가하더라도 경고 신호일 뿐 세션 보호를 대신하지 않습니다. 인증서 고정은 엔트리의 인증서 운영을 통제할 수 없는 직접 배포 앱에서 정상 인증서 교체를 장애로 만들 수 있어 적용하지 않습니다. 대신 cleartext 차단과 시스템 인증서만 신뢰하는 정책을 사용합니다.

## 잔여 위험과 운영 우선순위

1. 현재 공개 APK는 기존 설치자 업데이트를 위해 초기 디버그 인증서 계보를 유지합니다. 전용 운영 키 전환에는 앱 ID 변경 또는 재설치 공지가 필요합니다.
2. 영구 알림 보관함의 제목·본문·원본 payload는 필드 암호화하지만 사용자 식별자와 URL 등 검색용 메타데이터는 평문입니다. 루팅·후킹 공격자가 앱 프로세스의 정상 복호화 기능을 호출하는 경우까지 막지는 못합니다.
3. 출처 제한 WebMessage 채널은 레거시 JavaScript 인터페이스보다 좁지만 동일 출처 XSS를 무효화하지는 못합니다. 네이티브 폴링 비중을 늘리고 장기적으로 단발성 결과 회수 구조로 축소합니다.
4. 독립 모바일 침투 테스트와 실제 기기 기반 로그아웃·세션 이전·프록시 거부 검증은 아직 외부 인증을 받지 않았습니다.

보안 문제를 재현할 때 실제 쿠키, 토큰, 전체 알림 원문을 공개 이슈에 첨부하지 마세요. 신고 절차는 [SECURITY.md](../SECURITY.md)를 따릅니다.
